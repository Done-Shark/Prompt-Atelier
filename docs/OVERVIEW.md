# Prompt Atelier 项目说明

> 本地优先的 AI Prompt 与图片资产管理工具，同时适配 NovelAI 与 ComfyUI。
> 它不生成图片，只负责把「用过的好东西」沉淀下来。

## 1. 它解决什么问题

用 NAI / ComfyUI 创作一段时间后，通常会遇到四件事：

1. **Prompt 散落**：好用的提示词在聊天记录、记事本、历史图片里，想复用得翻半天。
2. **参数丢失**：图片存下来了，但 seed、steps、sampler、LoRA 权重这些生成参数没跟着走。
3. **Tag 不统一**：同一个 tag 有中英文两种写法、分类混乱，换个工具就不认识。
4. **角色卡散落**：SillyTavern 的 PNG / JSON 卡片堆在文件夹里，找起来只能靠文件名。

Prompt Atelier 把这四类资产收进一个本地应用：**Prompt 库、NAI 图库、ComfyUI 图库、Tag 库、RP 角色卡库**，共用一套文件夹、搜索、标签与备份机制。

## 2. 它是什么 / 不是什么

**是**：

- 一个本地单用户的桌面应用（Electron + 本地 HTTP 服务），数据全部落在本机。
- 一个「导入 → 整理 → 复用」的工作台：从图片反解 Prompt，从 Prompt 复制回生成工具。
- 一个可备份、可迁移、可自己改的工程：SQLite + 文件目录，没有云端账号。

**不是**：

- 不是生成器，不调用模型出图。
- 不是多用户协作平台，没有登录、权限、同步。
- 不是 Danbooru 客户端，内置词典只是起点，不追求全量覆盖。

## 3. 核心功能

### Prompt 库

- 按目标格式（NAI / ComfyUI）分开管理，支持文件夹、搜索、标签、收藏、示例图。
- **语义分块**：把一条 Prompt 拆成人物 / 服饰 / 动作 / 场景 / 风格等块，可整块启停、拖动排序。
- `positive` 是唯一事实来源，分块只是视图；只有显式编辑分块才反写原文，避免自动整理改变原始顺序。
- 一键复制为对应格式；支持从图片反解生成 Prompt。

### 图片库（NAI / ComfyUI 双模块）

- 扫描目录或上传导入，按 PNG 元数据自动识别归属与生成参数（模型、seed、steps、sampler、CFG、LoRA）。
- **原图逐字节保存**，不转码、不压缩；磁盘按「应用内文件夹结构」镜像存放，资源管理器里也能直接翻。
- 缩略图按内容哈希缓存，首次浏览生成，之后直接命中。
- 图片可多选、拖动排序、移动到文件夹、加入相簿；Tag 可直接双击 / F2 / 右键编辑，与 Tag 库联动。

### Tag 库

- 自动收录 Prompt 与图片里的 tag，补齐分类与中文翻译。
- 内置词典 + OpenAI 兼容接口 + Gemini + Danbooru 分类同步，人工修正优先，自动流程只补空。
- 支持批量翻译、批量改分类、锁定、清空译文；上千条时用虚拟滚动，只渲染视口附近的行。
- **改名 / 合并**会同步改写 Prompt 与图片引用，旧写法记为别名；**查找替换**支持正则与捕获组。
- 改名、批量修改、删除别名都可**撤销**（保留 20 步）。

### RP 角色卡库

- 面向 SillyTavern：导入 PNG（`chara` / `ccv3` 文本块）或 JSON 卡片，自动解析名称、标签、设定、简介与 Prompt。
- 左侧文件夹树 + 角色列表 + 详情，支持拖拽归档、批量选择 / 移动 / 删除、按名称与图片双重去重。
- 原图同样按文件夹镜像保存，文件名用角色名。

### 数据与备份

- 整库备份为一个文件夹：`data.json` + `images/` + `thumbs/`，覆盖 Prompt、图片、Tag、文件夹、相册与 RP 角色卡。
- 备份不含 API Key；恢复前自动留底当前 `data.json`，图片只覆盖不删除。
- 旧版本的扁平图片布局会在启动时自动迁移到镜像布局。

### 桌面打包

- `npm run dist` 产出 Windows 安装包（NSIS）与便携版；便携版数据放在 exe 同级 `data/`。
- 图标由脚本纯代码绘制，不依赖图形库。

## 4. 设计上的取舍与优点

1. **本地优先**：没有账号、没有云端，断网可用；数据目录可以整个拷走。
2. **原图不转码**：图片按源文件字节保存，扩展名跟随真实格式，避免二次压缩。
3. **两套存储各司其职**：索引与关系在 SQLite，原图在文件系统；图片用 sha256 去重。
4. **单一事实来源**：Prompt 的 `positive`、Tag 的 `reviewed`、字段 schema 都只有一处定义，减少前后端漂移。
5. **人工优先**：所有自动翻译 / 分类只补空，人工改过的条目默认锁定。
6. **可撤销**：Tag 的高风险操作有操作日志，改错能退。
7. **可测试**：后端 143 项测试覆盖存储、解析、导入、备份、迁移；前端纯函数有独立测试。
8. **可替换**：存储层优先 SQLite，不可用时自动回退 JSON；格式适配集中在 `shared/targets.js`。

## 5. 适合谁

- 经常用 NAI / ComfyUI 出图，想系统整理 Prompt 与参数的人。
- 用 SillyTavern 玩角色卡，需要本地卡片库的人。
- 想要一个能自己改、数据完全在本地的小工具的人。

不适合：需要多人协作、云端同步、在线生成或移动端的人。

## 6. 数据与隐私

- 所有数据默认保存在本机 `data/`（打包后为 `%APPDATA%/Prompt Atelier/data` 或便携版 `data/`）。
- 只有启用 AI 翻译 / Danbooru 同步时才会访问对应网络接口；API Key 只存在本机设置里，且不会写入备份。
- 仓库本身不包含任何用户数据、密钥或图片。

## 7. 技术栈

- 前端：React 19 + TypeScript + Vite，原生 CSS + 设计令牌，无 UI 框架。
- 桌面：Electron（无边框窗口 + 自定义标题栏），主进程 CJS，业务 ESM。
- 后端：Node.js 原生 `http`，零运行时依赖；SQLite（`node:sqlite`）+ 事务写入。
- 测试：`node:test`（后端 / 共享内核）+ Vitest（前端纯函数）。
